Command line

The program is sync-servers. With no command in a terminal it opens the full-screen interface; every task is also a command, for scripts and for anyone who prefers typing.

Commands

This reference is generated from the same definitions as sync-servers --help; sync-servers <command> --help prints the part for one command. A command acts on the site of the current folder unless it is given --site; see Which site a command means.

  • sites: List the sites
  • site add: Add a site and its first server; in a terminal, connect first and pick the root from the server
  • site edit: Change a site, with options or as JSON in your editor
  • site show: Show a site and its servers
  • site remove: Remove a site, its saved passwords and its sync records
  • site path: Print a site's local root (with shell integration, change to it)
  • server list: List a site's servers
  • server add: Add a server to a site; in a terminal, connect first and pick the root from the server
  • server edit: Change a server: asks again in a terminal, or takes options, or JSON in your editor
  • server remove: Remove a server, its saved passwords and its sync records
  • server test: Connect, sign in, check the remote root and show what the server offers; in a terminal, fix what it finds
  • server set-remote: Make a server the one synchronization uses
  • server set-testing: Make a server the Testing server, or clear the role
  • password set: Save a password or key passphrase in the OS credential store
  • password forget: Remove a saved password or key passphrase
  • cloak: Cloak files and folders so no operation touches them, in one site or every site, or list what is cloaked
  • uncloak: Remove cloaked paths or patterns, from one site or from the global patterns
  • sync: Synchronize a site with its Remote server: preview, then transfer
  • put: Put files or folders now, with a preview only when a decision is needed
  • get: Get files or folders now, with a preview only when a decision is needed
  • status: Show what changed on each side since the last sync; transfers nothing
  • diff: Show how the local and remote copies of a file differ
  • mark-synced: Record files as in sync without transferring them
  • state reset: Forget the sync records of a site and server; the next sync starts from scratch
  • config path: Show the folders sync-servers reads and writes
  • config edit: Edit the whole sites.json in your editor, also when it is not valid
  • doctor: Check Node.js, the folders, the credential store, the terminal and every site
  • shell-init: Print the "ssv" shell function that changes to a chosen site's folder (bash, zsh, fish, pwsh, cmd)
  • help: Show help for a command

Preview modes

sync, and put or get when a decision is needed, show a preview before anything moves. --preview chooses how:

Values of --preview
ModeShows the preview
tuiFull screen, row by row, with the results after the run. The default in a terminal.
editorAs a text file in your editor; see Editor mode.
plainAs numbered rows and typed commands; see Plain mode.
nonePrinted, followed by one yes or no question in a terminal. The default without a terminal.

Without --preview, the mode is none when nobody can answer: with --yes, --dry-run, --json, or no terminal. Otherwise it comes from SYNC_SERVERS_UI, else tui, which becomes plain with --plain, with TERM=dumb, or in a terminal that cannot be put in raw mode. --yes together with a preview mode is a usage error.

The terminal interface

Run sync-servers with no command. It opens at the site of the current folder, or at the list of sites. Everything works from the keyboard at 80 by 24, and ? on any screen lists every key of that screen. --ascii uses ASCII symbols only, and --no-color or NO_COLOR turns colour off; every symbol stands beside a word, so nothing is lost.

Every screen has the same frame. Two solid lines frame the content. While rows are hidden above or below what is shown, a dashed line marks that edge; at the first or last row it disappears. Under the bottom line, the menu lists the screen's keys as key = action, with a pipe between them, wrapping onto more rows on a narrow terminal. The last row shows messages, the progress of a running task, or the full text of the focused row.

Editor mode

--preview editor, or SYNC_SERVERS_UI=editor, writes the plan to a private temporary file and opens it in the first of SYNC_SERVERS_EDITOR, VISUAL and EDITOR, else Notepad on Windows or nano, then vi, elsewhere. An editor that returns at once, such as VS Code, needs its wait flag: SYNC_SERVERS_EDITOR="code --wait".

# sync-servers preview: My Site -> Production (SFTP)
# Put newer files to remote
# Files: 37 will be updated, 169 will be skipped, 12 need a decision
#
# Check or uncheck a box, or change the action word, then save and close to
# synchronize. Close without saving, or delete every row, to cancel.
#   put  get  skip  synced  delete-remote  delete-local
#
[x] put       1  img/hero.svg
[ ] resolve   3  css/site.css      # Changed locally and on the server.
[ ] put       4  .env              # Matches the sensitive pattern ".env".

The number identifies the row; the path is there to read and is checked against the number. A deleted row is skipped. A number the plan does not hold, a changed path, an unknown action, an action the file cannot take, or a resolve row left checked reopens the file with the problems as comments at the top. An edit can only choose among the planned rows; it can never add a path.

Plain mode

--plain, TERM=dumb, or a terminal without raw mode runs every flow as numbered prompts, with no alternate screen and no cursor movement, which screen readers and logging terminals follow. With no command it shows the sites as a numbered list and a menu for the chosen site. The preview prints numbered rows and takes commands:

Plain preview commands
CommandDoes
3, 1 4, 2-6Check or uncheck rows
p, g, s, m and row numbersSet Put, Get, Skip or Synchronized
x and row numbersDelete, asking where when both copies exist
all, noneCheck or uncheck every row that can run
diff 3Show how the two copies of a row differ
list, helpShow the rows, or the commands, again
goSynchronize the checked rows, after one question
qCancel, transferring nothing

Unattended runs

  • Without a terminal, nothing ever asks. A secret that cannot be found fails with E_AUTH; an unknown SSH host key is refused unless --host-key names it.
  • sync without --yes prints the preview and transfers nothing, so a script that forgets the flag does no harm.
  • --yes runs the checked rows. Rows that need a decision are never decided for you: they are reported, and the exit code is 3.
  • Deletes run only with both --delete and --yes, and past the mass-delete limit only with --allow-mass-delete as well.
  • --plan-out plan.json saves the plan; --plan-in plan.json runs it later, after checking that a fresh scan still matches what the plan was built from.
SYNC_SERVERS_PASSWORD="$DEPLOY_PASSWORD" \
  sync-servers sync --put --yes --site "My Site" --host-key SHA256:<fingerprint>

Shell integration

A program cannot change its shell's folder. sync-servers shell-init <shell> prints a small ssv function that runs sync-servers with --cd-file and then changes to the folder of the site you chose. It changes folder only to an existing local folder of a configured site.

Installing ssv
ShellAdd
bash, zsheval "$(sync-servers shell-init bash)" in ~/.bashrc, or zsh in ~/.zshrc
fishsync-servers shell-init fish > ~/.config/fish/functions/ssv.fish
PowerShellInvoke-Expression (& sync-servers shell-init pwsh | Out-String) in your profile
cmdsync-servers shell-init cmd > "%USERPROFILE%\bin\ssv.cmd", with that folder on PATH

Then ssv opens the sites and lands in the one you open, and ssv site path "My Site" goes straight there.

Exit codes

What the exit code means
CodeMeaning
0Done, or nothing to do
1Error: the command could not run
2Usage error, or no site could be chosen
3Finished, with failed rows or rows still waiting for a decision
4Cancelled
5Stopped by a safety guard: host key mismatch, insecure protocol, empty root or mass delete

JSON output

--json writes one JSON document to standard output and nothing else; progress and warnings go to standard error. Every document names its kind and version, so a script can tell when the shape changes:

{
  "schema": "sync-servers/status@1",
  "siteId": "3f2b7c1e-8a4d-4f6b-9c2e-1d5a7b9e0c31",
  "local": [{ "path": "css/site.css", "state": "local-changed" }],
  ...
}

The kinds are sites, site, site-removed, site-path, servers, server, server-removed, server-test, cloaking, cloaking-global, sync, status, diff, mark-synced, config-paths, doctor and error. Paths are site-relative, and secrets never appear.
